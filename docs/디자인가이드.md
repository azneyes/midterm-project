# 디자인 가이드 — KPA NOW v2

> 기획 5단계 "화면 기획"(발표자료 부록 B5 화면별 요소 분석표)의 요약본입니다. **코드의 화면 파일 맨 위 대응표와 번호·명칭이 같아야** 합니다(UI 25점 "기획과 일치").
> 이 가이드에 없는 화면은 만들지 않습니다(감점). 화면을 바꾸면 여기 → 코드 대응표 → 원칙 카드 순서로 같이 고칩니다.

```
[옆으로(tab)]  대회 │ 랭킹 │ 동호회 │ 소식 │ AI 코치
  T 대회 일정 ──쌓기(push)──▶ D 대회 상세 [옆으로(tab): 정보 | 대진표 | 결과] ──덮기(modal)──▶ E 참가 신청(예시) ──▶ 완료 안내(Dialog)
  R 선수 랭킹 ──쌓기(push)──▶ P 선수 프로필 ──덮기(modal)──▶ A AI 경기력 분석 카드
  K 내 동호회 (동호회 정보 + 회원 목록)
  N 협회 소식 (같은 화면에서 펼치기)
  C AI 코치  ──쌓기(push)──▶ V 영상 분석 결과
```

- 전환 3방식: **쌓기**(push/pop) · **옆으로**(NavigationBar · TabBar) · **덮기**(showModalBottomSheet · showDialog).
- 적응형(창 너비 기준, `LayoutBuilder`):
  - **600dp 이상**: T · R · C 목록 → 격자(GridView), P 선수 프로필 · K 내 동호회 → 정보 | 목록 2단
  - **840dp 이상**: 하단 메뉴(NavigationBar) → 측면 메뉴(NavigationRail), V 영상 분석 → 영상 | 피드백 2단
  - N 소식은 넓은 화면에서도 읽기 폭 최대 720dp
- 로그인 없음: "내 동호회"와 "나"는 db.json에 고정한 **예시 사용자**(서울 큐클럽, `mine: true` · `me: true`)다.
- 스카치 더블: 두 선수가 한 팀으로 번갈아 치는 대회. 카드(T-9) · 상세(D-9) · 신청 시트(E)에 같은 배지를 쓰고, 신청할 때 내 동호회 회원 중 파트너를 고른다(E-7). 파트너에게 실제 초대·알림은 없다.
- 실제 동작 없음: 참가 신청 · 영상 올리기 · 영상 재생 · AI 분석은 모두 **예시(SnackBar · 미리 작성한 결과)**. 선수는 모두 가상 인물.

## 4. 디자인 가이드 글 (위에서 정의한 명칭을 그대로 쓴다)

### 접수 상태·마감 안내 (T-5)
- **목적**: 대회 목록에서 지금 신청할 수 있는 대회를 바로 알아보게 한다.
- **내용**: 카드 맨 위에 상태 배지(접수중 · 진행중 · 종료)와 마감 안내 문구("접수 마감 D-5")를 둔다. 배지는 색과 글자를 함께 쓴다.
- **의도**: P01 시스템 상태의 가시성. TODO: 리뷰 근거.

### 정보 | 대진표 | 결과 (D-2)
- **목적**: 대회 하나에 대한 정보를 한 화면에서 찾게 한다.
- **내용**: 세 탭을 두고, 대회 상태에 맞는 탭을 먼저 연다(진행중 → 대진표, 종료 → 결과).
- **의도**: P06 · P07. TODO: 리뷰 근거.

### 참가 신청 버튼 · 신청하기 버튼 (D-5 · E-5)
- **목적**: 신청할 수 없는 상황에서 누르고 실패하는 일을 막는다.
- **내용**: 접수 기간이 아니면 참가 신청 버튼을 끄고 이유를 보여 준다. 시트에서는 부문 선택과 확인 사항 체크 전까지 신청하기 버튼이 꺼져 있다.
- **의도**: P05 오류 예방. 실제 신청은 하지 않는다(예시 완료 안내만).

### 스카치 더블 파트너 선택 (T-9 · D-9 · E-7)
- **목적**: 스카치 더블 대회에 함께 나갈 파트너를 내 동호회 회원 중에서 바로 고르게 한다.
- **내용**: 목록 카드에 스카치 더블 배지(T-9), 정보 탭 맨 위에 경기 방식 설명(D-9), 참가 신청 시트에 동호회 회원 목록(E-7). 파트너를 고르기 전에는 신청하기가 꺼져 있고, 고르면 "○○님과 신청하기"로 바뀐다.
- **의도**: P06 · P05 · P10. TODO: 리뷰 근거. 실제 초대·알림·신청은 없다(예시 완료 안내만).

### 오류 안내·다시 시도 (T-7 외 모든 GET 화면)
- **목적**: 데이터를 못 받았을 때 빈 화면 대신 무엇이 잘못됐는지 알린다.
- **내용**: 오류 아이콘 · 무엇을 못 불러왔는지 · 다시 시도 버튼.
- **의도**: P09. 빈 상태(EmptyView)와 구분해 "없는 것"과 "못 받은 것"을 다르게 보여 준다.

### AI 경기력 분석 카드 (P-4 · A)
- **목적**: 경기 기록을 직접 해석하지 않아도 강점·약점과 연습 방법을 확인하게 한다.
- **내용**: 한 줄 요약 → 지표 막대 4개 → 강점 → 약점 → 추천 연습 → 예시 고지.
- **의도**: P07 · P02 · P10. 중간고사에서는 미리 작성한 값만 보여 준다(AI 호출 없음).
